# Customer-Facing UI — Design Spec

**Date:** 2026-07-28
**Builds on:** the RAG FastAPI backend (`rag/api.py`, `POST /answer` → `{text, status, verdict, sources}`).
**Goal:** a live, customer-facing URL a non-programmer IR professional can open, ask a question, and understand the result — with no code, field names, or jargon.

---

## 1. Approach (decided)

A **single polished HTML/CSS/JS page served by the existing FastAPI backend at `/`.**
One Render service serves both the UI and the API → one live URL, simplest deploy.
Layers stay separated: the page is a static asset that talks only to `POST /answer`;
it never imports or knows about retrieval/data internals.

## 2. What the assessment requires (honoured here)

- Live customer-facing URL, not an API/console/JSON. ✓ (served page)
- Non-programmer usable; no internal field names / validation vocabulary. ✓
- Behaves sensibly on success / empty / partial / failure — each a readable message. ✓ (5 states)
- Conveys *why the intelligence is worth paying for*, not just the data. ✓ (verified badge, why-now, second-AI check)
- Every visible word is a claim we can back. ✓ (copy audited against real behaviour)
- Presentation is third priority — clean and honest, not over-built. ✓ (one page, YAGNI)

## 3. Files

- Create: `frontend/index.html` — structure + copy.
- Create: `frontend/styles.css` — styling (one system, light, professional).
- Create: `frontend/app.js` — calls `/answer`, renders each `status`.
- Modify: `rag/api.py` — mount `frontend/` as static and serve `index.html` at `/`.
- Test: `tests/test_api.py` — assert `/` returns the page (200 + contains the search box).

## 4. Layout (top → bottom)

1. **Header** — product name + subline: "Ask about verified family offices — who to contact, why, and why now."
2. **Search** — one large input + "Ask" button; below it, clickable **example-query chips**:
   "family offices in New York", "firms with a recent investment signal",
   "single family offices", "who leads Duquesne Family Office?".
3. **Answer area** — renders `status`:
   - `answered` → answer card; footer line "Based on N verified records" + **source chips**;
     a small **"✓ checked by a second AI"** badge (the grounding control shown as value, not jargon).
   - `declined` → calm amber card: "I can't answer that confidently from verified data…".
   - `no_match` → "No family office matches that — try broader terms.".
   - `empty` → gentle "Type a question to begin.".
   - `error` → "Momentarily unavailable — please try again." (never a trace).
4. **Footer** — "Answers come only from verified records; the system declines when evidence is thin."

## 5. Data flow

```
user types -> app.js POST /answer {query}
           -> {text, status, verdict, sources}
           -> render(status): card style + text + (sources as chips if answered)
```
Loading state: button shows a spinner / "Thinking…"; input disabled during the call.

## 6. Error handling (UI side)

- Network failure / non-200 → render the same friendly `error` card, never a raw error.
- Empty input → handled client-side as `empty` (don't even call the API).
- Long answers → card scrolls internally; page never breaks layout.

## 7. Testing

- Backend: `/` returns 200 and includes the search input (page served).
- Manual/live: run each of the 5 states in the browser and confirm each renders its
  own readable card (recorded for the doc note's "live queries I ran").

## 8. Deploy — all on Vercel (user's connected account)

Everything ships to Vercel (github ↔ vercel connected → push auto-deploys):
- **FastAPI app runs as a Vercel Python serverless function.** `api/index.py`
  exposes the ASGI `app`; `vercel.json` routes every path to it, so one function
  serves both `/` (the page) and `/answer`.
- **The embedding model is bundled in the repo** (`rag/models/potion-base-8M/`)
  and loaded from that local path — no runtime HuggingFace download on cold start.
- **In-memory Qdrant** is built once per warm instance (module-level cache), so
  only a cold start pays the ~1-2s rebuild.
- **Secrets** (`GROQ_API_KEY`, `GROQ_API_KEY_2`) are set in the Vercel
  project's Environment Variables — `.env` is never deployed.
- The Vercel URL is the Task-1 "live customer-facing URL" deliverable.
- **Fallback:** if the ML deps exceed the serverless size/time limit, split —
  keep the page on Vercel, move the FastAPI backend to Render, point the page at it.

## 9. Out of scope (YAGNI)

No accounts/login, no history, no filters UI (the query text drives filtering),
no dark mode, no analytics. One question → one grounded, honestly-stated answer.
